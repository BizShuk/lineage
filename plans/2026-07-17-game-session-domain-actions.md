# Game Session Domain Actions Implementation Plan

> For agentic workers: execute each task with `test-driven-development`; do not edit `WorldScene` or visual files, and do not commit this task.

Goal: provide one production `GameSession` boundary used by UI and browser E2E so every player action uses the same validated domain rules and serializable state.

Architecture: `GameSession` composes `WorldController` and the existing inventory, quest, progression, and combat reducers. `WorldController` remains authoritative for timed world simulation, monsters, player position, combat, loot, boss state, and quest signals generated by the world. `GameSession` validates NPC proximity and content ownership, executes non-timed player actions, synchronizes the controller, derives the ending from claimed quest state, and seals complete saves.

Tech stack: TypeScript, Vitest, existing content catalog and domain reducers.

## Global Constraints

- Tests must fail for the expected missing behavior before production code is added.
- No direct setting of `baphometDefeated` or `finalReportComplete` by callers.
- NPC actions require the current map and Chebyshev distance of at most one tile.
- Quest acceptance uses class and prerequisite validation from `startQuest`.
- Buying validates the current NPC's stock; selling requires a merchant-capable NPC.
- Equipment, consumables, MP, spell reagents, and bow ammunition use existing inventory rules.
- `WorldScene`, UI, and visual files are out of scope for this task.
