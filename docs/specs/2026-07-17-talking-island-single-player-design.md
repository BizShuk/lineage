# 《天堂》說話之島單機致敬版設計規格

日期：2026-07-17

## 1. 目標

建立一款可在桌面瀏覽器離線執行的單機角色扮演遊戲，玩法、操作、畫面構圖與成長節奏以 2000–2003 年台灣早期《天堂》說話之島版本為基準。玩家能從建立角色開始，完成村莊整備、野外狩獵、黑騎士事件、說話之島地監探索與最終首領戰，並在結局後繼續自由探索。

本作是非商業單機致敬作品。程式碼、圖像、音效與音樂均重新製作，不擷取或散布原始遊戲客戶端資源。內容名稱與規則可用於辨識早期版本，但交付物不包含 NCsoft 或遊戲橘子的商標素材。

## 2. 成功標準

完成版本必須同時滿足：

- `王族`、`騎士`、`妖精`、`法師`皆可建立並完成遊戲。
- 滑鼠與鍵盤操作、戰鬥、施法、物品、裝備、商店、倉庫、NPC 對話、任務及地圖切換全部可用。
- 說話之島村、稻草人區、野外、海岸、黑騎士區、地監一樓與地監二樓皆可探索。
- 主線能從角色建立一路完成至地監首領及村莊尾聲。
- 三個本機存檔欄、自動存檔、手動存檔、匯出與匯入均可恢復完整狀態。
- 規則測試、內容完整性測試、整合測試與瀏覽器端到端測試通過。
- 正式版本可透過文件所載命令啟動，遊玩流程沒有未處理的瀏覽器 console error。

## 3. 範圍

### 3.1 納入

- 四個早期職業與六項能力值：力量、敏捷、體質、智力、精神、魅力。
- HP、MP、AC、負重、正義值、等級與經驗值。
- 即時點擊戰鬥、近戰、弓箭、魔法、藥水、狀態效果與死亡損失。
- 武器、防具、消耗品、材料、任務物品、魔法書、箭矢與金幣。
- NPC 商店、倉庫、旅館、訓練區、任務與分階段對話。
- 野外與地監怪物的巡邏、警戒、追擊、攻擊、返巢、死亡、重生與掉落。
- 早期風格 HUD、物品窗、裝備窗、魔法窗、狀態窗、對話窗及訊息列。
- 三個角色存檔欄、設定、資料匯出與匯入。

### 3.2 不納入

- 多人網路連線、帳號、伺服器、玩家交易與聊天後端。
- PVP、血盟、攻城戰、交易所與課金。
- 說話之島以外的亞丁大陸、無限程序生成或無限等級內容。
- 自動練功、掛機戰鬥與現代 MMORPG 自動尋路。

## 4. 玩家流程

```text
主選單
└── 選擇存檔欄
    └── 建立角色
        └── 稻草人訓練與基礎操作
            └── 說話之島村補給與職業引導
                └── 野外狩獵及裝備成長
                    └── 黑騎士事件
                        └── 地監一樓探索
                            └── 地監二樓首領
                                └── 返回村莊完成尾聲
                                    └── 自由探索
```

初次通關時間預估為 3–5 小時。經驗與掉落平衡以單人完成島上篇章為目標，不要求重複長時間刷怪。

### 4.1 最低可交付內容量

| 類型 | 最低內容量 |
| --- | --- |
| 職業 | 4 個完整職業，各自具有可辨識的初始能力、裝備與魔法／技能路線 |
| 等級 | 完整支援等級 1–15；正常通關角色預期達等級 12–15 |
| 區域 | 本規格列出的 7 個區域，包含所有出入口與安全區規則 |
| NPC | 至少 15 名具功能或對話的 NPC |
| 敵人 | 至少 10 種普通怪物、黑騎士精英群、黑騎士隊長克特事件與首領巴風特 |
| 物品 | 至少 40 件武器、防具、消耗品、魔法書、箭矢與任務物品 |
| 魔法／技能 | 至少 20 項可使用能力，按職業與條件分配 |
| 任務 | 6 階段共通主線、4 條職業引導分支及至少 6 個支線任務 |

## 5. 世界與內容

### 5.1 區域

| 區域 | 功能 |
| --- | --- |
| 說話之島村 | 安全區、商店、倉庫、旅館、職業引導與主線樞紐 |
| 稻草人區 | 等級 1–5 教學、無致命風險的操作練習 |
| 北部野外 | 初階狩獵、材料與基礎裝備 |
| 海岸 | 遠程及群聚敵人、支線任務 |
| 黑騎士區 | 中後期事件、精英敵人與地監前置任務 |
| 說話之島地監一樓 | 不死系敵人、資源消耗與探索 |
| 說話之島地監二樓 | 高階不死系敵人、首領與篇章結局 |

所有必要區域必須彼此可達。內容檢查會以通行網格驗證出生點、出口、任務目標與首領位置間存在有效路徑。

### 5.2 角色與成長

| 職業 | 定位 | 單機版特色 |
| --- | --- | --- |
| 王族 | 均衡近戰、魅力 | 鼓舞型自我強化與較高 NPC 交易收益 |
| 騎士 | 高 HP、近戰 | 穩定命中、防禦與藥水效率 |
| 妖精 | 弓箭、敏捷 | 遠程風箏、自然系輔助與箭矢管理 |
| 法師 | 魔法、精神 | 高爆發、控制、治療與 MP 資源管理 |

六項能力值影響角色初始數值與成長。AC 採早期版本方向：數字越低，防禦表現越好。負重超過門檻會降低或停止自然回復；死亡會回到村莊並損失一部分當前等級經驗，但主線關鍵物品不會遺失。

### 5.3 敵人與事件

敵人內容以早期說話之島的辨識度為基準，包括哥布林、妖魔、侏儒、狼人、蜘蛛、殭屍、骷髏、食屍鬼、魔像與黑騎士等類型。屬性、出現區域與掉落表由內容資料定義，不寫死在場景程式中。

港口的黑騎士隊長 `克特` 與黑騎士事件是進入地監後段的主線門檻；地監二樓首領 `巴風特` 是篇章完成條件。首領死亡狀態會存入世界狀態，結局後不會因普通地圖重載而立即重生。

## 6. 操作

| 輸入 | 行為 |
| --- | --- |
| 滑鼠左鍵點地面 | 移動至選定位置 |
| 滑鼠左鍵點敵人 | 走至攻擊距離並連續攻擊 |
| 滑鼠左鍵點 NPC／物件 | 接近並互動 |
| `WASD`／方向鍵 | 八方向移動 |
| `Space` | 攻擊最近的有效敵人 |
| `E` | 與最近的 NPC 或物件互動 |
| `Tab` | 依距離切換附近敵人 |
| `F5–F12` | 使用八格快捷列物品或技能 |
| `I` | 開關物品欄 |
| `C` | 開關角色及裝備窗 |
| `S` | 開關魔法／技能窗 |
| `Q` | 開關任務窗 |
| `M` | 開關區域地圖 |
| `Esc` | 關閉最上層視窗或開啟暫停選單 |
| 滑鼠滾輪 | 在允許範圍內縮放畫面 |

點擊敵人後會持續普通攻擊，直到敵人死亡、超出追擊距離、玩家移動取消、武器條件失效或玩家死亡。遊戲不提供現代式自動尋路；點擊移動只處理可見地圖內的短程尋徑。

## 7. 畫面與聲音

遊戲採 2D 斜俯視像素風格。內部邏輯畫布以接近早期 `640×480` 的構圖呈現，再以整數倍率或適當濾鏡放大至現代瀏覽器視窗。角色比例、地形密度、移動速度、攻擊停頓與介面配置以早期台灣《天堂》觀感為參考。

主要畫面由中央世界視窗、右側角色狀態與功能區、底部訊息列及快捷列組成。介面包含：

- 主選單、存檔欄與角色建立。
- HP、MP、等級、經驗、AC、負重、正義值與目標資訊。
- 角色、裝備、物品、魔法、任務、地圖、商店、倉庫、對話及設定視窗。
- 戰鬥訊息、取得物品、任務進度與系統錯誤訊息。

角色至少具待機、八方向移動、攻擊、受擊、施法與死亡狀態。效果包括近戰揮擊、箭矢、魔法、傷害數字、升級、掉落與區域環境色調。

聲音包含區域環境音、戰鬥、魔法、掉落、UI 回饋及背景音樂。音樂、環境音與效果音可分別調整或靜音；素材必須可合法隨專案散布。

## 8. 技術架構

採用 `Phaser + TypeScript + Vite`。遊戲規則不直接依賴 Phaser 場景，使規則能在無瀏覽器渲染環境下測試。

```text
Web App
├── Phaser 場景層
│   ├── 啟動、主選單、角色建立
│   ├── 世界、地監、戰鬥呈現
│   └── HUD、對話、商店與功能視窗
├── 純 TypeScript 規則層
│   ├── 角色、屬性、戰鬥、AI、掉落
│   ├── 任務、物品、裝備、商店、經濟
│   └── 世界狀態、時間、事件與命令
├── JSON 內容層
│   ├── 地圖、NPC、怪物、生成點
│   ├── 任務、對話、物品、掉落表
│   └── 職業、魔法、平衡與繁體中文文字
└── 儲存層
    ├── IndexedDB 存檔 repository
    ├── schema 驗證與版本遷移
    └── JSON 匯出、匯入與備份
```

場景以命令呼叫規則層，例如移動、攻擊、使用物品、購買與接受任務。規則層產生狀態變更與領域事件，場景依事件播放動畫、音效與 UI 回饋。儲存層只序列化穩定的遊戲狀態，不保存 Phaser 物件或暫時動畫狀態。

## 9. 存檔

- 提供三個獨立角色存檔欄。
- 地圖切換、任務階段完成、死亡重生及返回主選單前自動存檔。
- 暫停選單提供手動存檔；戰鬥中不可手動存檔。
- 存檔保存角色、能力、等級、經驗、位置、裝備、背包、快捷列、任務、NPC／首領狀態及設定。
- 每份存檔包含 `schemaVersion`、遊戲版本、更新時間與校驗資訊。
- 匯入資料先在記憶體驗證，通過後才取代目標欄；取代前保留最近一份自動備份。
- 無法遷移或損壞的存檔不得被靜默覆寫，玩家可下載原始資料並選擇備份或新遊戲。

## 10. 錯誤處理

- 啟動時驗證地圖、NPC、怪物、物品、掉落、任務與對話的 ID 引用。
- 內容驗證失敗時停止進入遊戲，顯示可辨識的內容錯誤與來源 ID。
- 非關鍵圖像或音效載入失敗時使用替代素材，並記錄資源路徑。
- 關鍵地圖或規則資料載入失敗時返回主選單，不建立不完整存檔。
- 瀏覽器分頁失焦或遊戲暫停時停止世界與戰鬥計時。
- 未預期的執行錯誤會暫停遊戲、嘗試保留最近有效狀態，並顯示繁體中文恢復選項。

## 11. 測試與驗收

### 11.1 自動測試

| 層級 | 覆蓋範圍 |
| --- | --- |
| 單元測試 | 能力衍生值、命中、傷害、AC、負重、攻速、經驗、掉落與任務狀態 |
| 內容完整性 | ID 引用、重複 ID、地圖出口、生成點、掉落來源、任務目標與可達性 |
| 整合測試 | 戰鬥到掉落、拾取到背包、商店到裝備、死亡到重生、存檔到載入 |
| 瀏覽器 E2E | 四職業建角、移動、攻擊、NPC、商店、倉庫、快捷列、地監、首領與結局 |

### 11.2 視覺驗證

在主選單、角色建立、村莊、野外、黑騎士區、地監一樓、地監二樓，以及角色、背包、魔法、商店與設定視窗建立基準截圖。人工檢查文字截斷、圖層順序、碰撞錯位、縮放模糊、HUD 遮擋與不同視窗尺寸。

### 11.3 發行驗證

- 安裝、格式檢查、型別檢查、單元／整合／E2E 測試與 production build 全部成功。
- 依 README 從乾淨環境啟動 production build，可建立角色並載入遊戲。
- 執行完整主線通關測試，確認結局旗標、存檔重載與自由探索。
- 檢查瀏覽器 console，不得存在未處理例外、失敗的必要資源請求或存檔錯誤。

## 12. 實作分期

實作計畫將依以下可驗收順序展開，但所有階段共同構成最終交付，不能以垂直切片取代完整目標：

1. 專案骨架、規則核心、內容 schema 與測試基礎。
2. 地圖、移動、鏡頭、碰撞、互動與早期 HUD。
3. 四職業、戰鬥、AI、死亡、掉落、物品與裝備。
4. 村莊 NPC、商店、倉庫、對話、任務與職業魔法。
5. 全部野外區域、黑騎士事件、地監一至二樓及首領。
6. 存檔、設定、匯出匯入、錯誤恢復與內容驗證。
7. 原創美術、動畫、特效、音效、音樂與介面完善。
8. 平衡、完整通關、視覺檢查、E2E、production build 與交付文件。

## 13. 已確認決策

- 交付平台：桌面瀏覽器單機版。
- 技術方案：Phaser + TypeScript。
- 參考版本：2000–2003 年台灣早期《天堂》說話之島。
- 內容定位：玩法與辨識度貼近參考版本，所有素材重新製作。
- 網路範圍：不實作多人連線。
- 完成範圍：完整說話之島篇章，而非只有戰鬥原型。
